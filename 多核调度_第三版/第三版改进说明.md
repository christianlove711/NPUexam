# 第三版改进说明

第三版从队友交付的“多核调度_完整版”复制独立建立，保留第一版回退、第二版候选、官方评估、三问配对、续跑和报告流程。新增 `solver_idblocks.py`，并在 `worker.py` 的候选池中评估其方案。旧运行目录与第三版新运行目录相互独立；不能将不同目录的若干行拼成同一次实验。

## 新增候选的数学含义

先把题目计算图收缩为非 COPY 操作的依赖 DAG，使用编号最小优先的拓扑排序。将该顺序按固定操作数划成连续区间，区间即子图。由于每条原依赖都从较早位置指向较晚位置，跨区间边只会从较小编号子图指向较大编号子图；把各核心的子图列表也保持编号递增，便得到容易校验的初始方案。

分核时顺序考虑每个子图，试放到所有核心，用核心空闲时刻、前驱预计完成时刻和块内计算／输入量代理估计完成时间，选择代理完成时间最早的核心。该代理沿用场景 A 的等待常数，用来产生额外候选；对问题二、三尤其不代表其真实通信、内存、DDR 或 Cache 行为。任何候选的合法性及得分都由对应官方评估器决定。

规模不超过 1,000 个非 COPY 操作时，尝试每块 32 与 64 个操作；1,001～5,000 个时尝试 32 与 128；更大时尝试 128 与 512。这些阈值是候选生成预算，并非经 100 例验证的最优参数。保留第二版候选和第一版回退，最终按官方 `(Makespan, 新增 COPY 字节数)` 字典序选择。

# 队友交接记录

## 当前项目结构

`run_all.py` 是唯一推荐批量入口；`solver_v2.py` 生成候选；`worker.py` 调用官方评估器并执行局部搜索；`reports.py` 从 CSV 生成图。官方 `code/`、`data/` 和第一版都在上一级，不能为了提高成绩直接修改评估器或固定配置。

用户已明确：**Mac 只用于编写算法，完整评估及搜索在性能更强的电脑上运行**。接手后按这个分工执行，文档整理不触发 Mac 上的批量实验。

阅读入口：[环境与命令](运行与环境说明.md)、[数学模型](算法与实验方案.md)、[函数与数据流](代码结构与函数说明.md)、[图表及字段](结果字段与图表解读.md)。

## 接手时先检查

1. 阅读本目录 `README.md` 和 `算法与实验方案.md`，确认 Python 环境与目录相对位置。
2. 查看目标运行目录的 `manifest.json`。`status=complete` 且 `reports/failures.csv` 没有数据行表示清单所选范围完成；正式全量还须确认 100 个用例、2～5 核、三问各 400 行汇总及验证通过。
3. 需要续跑时使用 `--resume`；需要重试失败任务时再加 `--retry-failed`。不要手工改写已经保存的成绩或把不同运行目录拼成同一次实验。
4. 算法改动后，将对应代码复制到目标运行电脑，在该电脑运行接口测试、定向验证、`--quick` 和全量实验。新算法正式对比使用新运行目录，记录改动、运行编号、完成情况和结论。

## 结果解释

题一、二的 `v1_makespan` 是同问题第一版基线。题三 `paired_no_l2_makespan` 与 `paired_with_l2_makespan` 共用题二最终方案；`problem_3/makespan` 可能属于另一个 L2 优化方案。Cache 本身提升只从配对列计算。

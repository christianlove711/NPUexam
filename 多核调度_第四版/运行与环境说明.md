# 环境安装与实验运行说明

本项目按“Mac 编写算法，强 CPU 电脑执行实验”的分工使用。下列评估、快速模式和搜索命令均供目标运行电脑执行。Mac 上可阅读、修改代码和文档；本说明的更新不要求在 Mac 上重跑实验。

## 1 必须一起复制的文件

目标电脑需要完整保留下列相对位置，最外层文件夹名称可以改变：

```text
赛题附件根目录/
├── code/                         # 官方评估器及核内调度
├── data/                         # 100 个 case_*.json 和 config.txt
├── docs/                         # 题目和官方说明
├── 多核调度_第一版/
│   └── code/                     # 第二版会导入第一版的图预处理和求解器
└── 多核调度_完整版/
    ├── run_all.py
    ├── solver_v2.py
    ├── worker.py
    ├── reports.py
    ├── verify_run.py
    ├── requirements.txt
    ├── tests/
    ├── skills/
    └── runs/                     # 只有需要续跑旧实验时才必须复制
```

不要只复制 `多核调度_完整版/`。`solver_v2.py` 会按自身位置寻找上一级的官方代码和第一版代码；当前实现没有另设官方代码路径的命令行参数。即使运行个别用例，入口仍检查 `data/` 中是否有 100 个 `case_*.json`，所以必须带齐数据。

虚拟环境 `.venv`、`__pycache__` 和 `matplotlib_cache` 不需要跨系统复制；在目标电脑重新安装环境。需要续跑时复制完整的那一次运行目录，包括 `manifest.json`、`jobs/`、`plans/` 和已存在的 `search_jobs/`。

## 2 安装环境

使用 64 位 Python 3.11～3.13。现有端到端验证是在 macOS 的 Python 3.13 环境完成；Windows 路径和子进程调用按跨平台方式编写，尚未在本项目中记录 Windows 实机验收。

求解与模拟依赖标准库，Matplotlib 用于画图。无需 MATLAB、GPU 或 CUDA。以下示例都在**赛题附件根目录**执行。

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r 多核调度_完整版/requirements.txt
.\.venv\Scripts\python.exe 多核调度_完整版/run_all.py --quick
```

macOS/Linux 目标运行电脑：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r 多核调度_完整版/requirements.txt
.venv/bin/python 多核调度_完整版/run_all.py --quick
```

直接调用虚拟环境内的 Python 可避免终端激活方式的差异。后文统一写 `python`，实际使用时替换成上述虚拟环境解释器路径即可。建议先保持默认并行度；较大的图会占用较多内存，增加 `--workers` 不保证同比加速。

## 3 常用运行命令

完整实验：

```bash
python 多核调度_完整版/run_all.py
```

它先完成 100 个用例的单核基准和三问的 2～5 核必需评估，再进入追加搜索。默认的 10 小时只约束追加搜索，**不表示整个程序保证在 10 小时内结束**。

仅做全量必需评估，暂不做局部搜索：

```bash
python 多核调度_完整版/run_all.py --search-hours 0
```

快速验证：

```bash
python 多核调度_完整版/run_all.py --quick
```

默认选择 `case_001`、`case_019`、`case_035`，核数为 2、4；仍计算单核点和三问结果。只要传入 `--quick`，本次调用就不进入追加搜索。

定向运行：

```bash
python 多核调度_完整版/run_all.py --cases case_019 case_035 --cores 2 4 --search-hours 0
```

### 全部参数

| 参数 | 新运行默认值 | 实际含义 |
|---|---|---|
| `--quick` | 关闭 | 使用快速用例和 2/4 核默认值，并关闭本次追加搜索 |
| `--cases` | 全部 100 例 | 输入不带 `.json` 的名称；显式指定时优先于快速模式的默认用例 |
| `--cores` | `2 3 4 5` | 可指定不重复的 2～5 核；显式指定时优先于快速模式默认核数 |
| `--workers` | `min(4,max(1,CPU逻辑核数//2))` | 同时启动的 Python 评估子进程数；不是模拟 NPU 的核数 |
| `--search-hours` | `10` | 必需评估之后的搜索提交预算，单位小时；`0` 表示跳过 |
| `--timeout-minutes` | `30` | 一个 worker 任务的超时上限；该任务可能包含多次官方评估，不是每个候选各有 30 分钟 |
| `--resume` | 无 | 指定已有运行目录，继续它的任务 |
| `--retry-failed` | 关闭 | 重试已有 `status=error` 结果的任务 |
| `--no-plots` | 关闭 | 不生成或要求检查 PNG；CSV 和数值验证仍保留 |

同一次运行无法在入口中只选择某一道题，三个问题按固定顺序执行。正式默认实验的结果规模是：100 条单核记录，题一至三各 400 条多核汇总记录，共 1,300 个必需任务；这不是官方评估函数的调用总次数，因为一个任务会比较多个候选。

## 4 进度和时间预算

阶段顺序为 `singlecore` → A 的 `required` → B 的 `required` → L2 的 `required` → 汇总 → 可选 `search` → 绘图及验证。日志中的 `pending` 是当前阶段尚需提交的任务数。

追加搜索目前每组配置只考察一次有限邻域，不会持续循环到用满 10 小时。任务全部考察完会提前结束；预算耗尽后不再提交新的搜索任务，但已运行的任务会继续到完成或超时。题二搜索改进方案后，题三配对需要重算，这部分保证结果一致性的工作也可能发生在预算到期之后。

`--workers` 增大的是用于运行模拟器的 CPU 并行度。`--cores` 改变的是题目模拟的 NPU 核心数。换强 CPU 电脑主要减少程序运行的现实时间；在方案、评估代码与配置相同时，模拟 Makespan 应保持一致。时间预算内完成的搜索任务数量可能随电脑性能变化，因而最终选中的方案可能不同。

## 5 新运行和断点续跑

每次未指定 `--resume` 的调用都会建立 `runs/年月日_时分秒_随机后缀/`。旧实验不被新运行覆盖。显式续跑会更新该目录的最终方案、汇总和图表，这是同一次实验的后续处理。

```bash
python 多核调度_完整版/run_all.py --resume "多核调度_完整版/runs/已有运行目录"
```

续跑默认继承清单中的用例、核数、并行度、超时和搜索预算；运行器会检查用例列表、核数列表、固定配置文件哈希是否匹配。它**不检查算法源码和计算图的内容哈希**。因此算法改动后的正式对比应新建运行；为修复运行器故障而续跑时，要在交接记录中写明改动。

成功且未过期的任务会被跳过。已有错误结果在加 `--retry-failed` 后重试；没有生成结果文件的任务，在普通续跑时也会重新提交。题三保存了题二方案的哈希，题二文件变化时，相关题三记录会被视为过期并重算。

当前清单中的 `quick` 字段记录创建时是否使用快速模式，续跑是否跳过搜索则由**本次命令是否传入 `--quick`**控制。为明确只补结果或图表，可以传 `--search-hours 0`。

结束进程时可以用 Ctrl+C；正常捕获后状态为 `interrupted`。强制关机或直接结束进程可能留下 `running` 状态。完成的任务已写入文件，但正在评估的 worker 没有候选级断点，下次可能要重做整个任务。

本机留下的全量运行目录为 `runs/20260923_110536_a21981`，它只完成了部分单核基准。复制到目标电脑后，如需继续并启用搜索：

```bash
python 多核调度_完整版/run_all.py --resume "多核调度_完整版/runs/20260923_110536_a21981" --search-hours 10
```

## 6 状态与验收

| 状态或退出码 | 含义 |
|---|---|
| `running` | 运行中；强制中断后也可能保留此状态 |
| `interrupted` | 主入口捕获了 Ctrl+C，可续跑 |
| `incomplete` | 缺少必需结果、绘图失败或结果验证不通过 |
| `complete` | 本清单选择的必需范围及本次要求的检查完成；不保证所有搜索候选都成功 |
| 主入口退出码 `0` / `1` / `130` | 分别表示完成、结果不完整、用户中断；参数解析错误通常为 `2` |
| worker 记录 `returncode=124` | 运行器判定该 worker 超时 |

正式实验验收要同时确认 `manifest.json` 中有 100 个用例、`cores` 覆盖 2～5，`status=complete`，三问各有 400 条汇总，`failures.csv` 无数据行，`validation.json` 为 `ok`。再查看候选错误与可选搜索失败记录，不能只看 PNG 是否存在。

```bash
python 多核调度_完整版/verify_run.py "多核调度_完整版/runs/已有运行目录"
```

纯数值运行添加 `--no-plots`。校验脚本检查已保存文件之间的覆盖及对照关系，不会重跑模拟器，也不证明最优性。

## 7 常见情况

| 现象 | 排查与处理 |
|---|---|
| `Official evaluator is missing` / `First version is missing` | 检查是否复制完整目录，并保留上述相对位置 |
| 用例数量不是 100 | 检查 `data/` 是否缺文件，或意外加入了额外的 `case_*.json` |
| `No module named matplotlib` | 用运行入口的同一个 Python 安装 `requirements.txt`，然后对原目录续跑补图 |
| 大图很久没有新进度 | 一个 worker 需要完成本组候选后才写最终任务结果；观察结果文件数量，必要时在目标电脑调整超时 |
| 超时或内存不足 | 适当降低并行度，针对性提高单任务超时，然后续跑；不要为提速改官方容量和带宽 |
| `Resume mismatch` | 用例、核数或配置哈希发生变化；恢复原条件续跑，或建立新运行 |
| `complete` 但只画了 1、2、4 核 | 查看清单；快速模式本来就没有 3、5 核数据 |
| `worker_failures.csv` 存在但本次已成功 | 该文件可能保留上一轮续跑的记录；结合当前 jobs、验证结果和清单判断，不只看文件是否存在 |

单独补图可在 `多核调度_完整版` 目录执行：

```bash
python -c "from reports import build_plots; build_plots('runs/已有运行目录')"
```

此命令只读取现有 CSV，不刷新汇总表或更新清单。需要完整重建和验收时，使用 `run_all.py --resume ... --search-hours 0`；有缺失任务时该命令会继续执行评估。

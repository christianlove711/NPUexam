# 两次全量结果分析与 NPU_8 修订

本次补充完整分析昨天三问全量运行 `20260923_220123_13c740` 和今天问题一运行 `20260924_161743_fb450c`。上一轮仅核查今天问题一结果及两个功能样例，没有完整分析昨天 B/L2，且未将其最优方案纳入保底；本次已纠正。所有统计来自保存的实际记录，未重新运行全量实验。

## 问题一为什么进步

400 组中 388 组改善、12 组持平、0 组退步。五核平均加速比提高 55.79%；98 个 case 改善、2 个持平。五核子图数中位数由 69.5 降至 7，88 个 case 减少额外搬运。

按今天保留的候选记录，依次保留已有搜索、A 局部精修、独立分量、affinity、chain 的累计最优，五核平均加速比新增 1.275530，可拆为：

| 加入的候选阶段 | 平均加速比增量 | 占总增量 |
|---|---:|---:|
| A 局部精修 | 0.047705 | 3.74% |
| 独立分量分核 | 0.339104 | 26.59% |
| affinity 大张量聚类 | 0.874487 | 68.56% |
| 直线链融合 | 0.014234 | 1.12% |

这是有顺序的历史候选择优分解，不是重新运行各策略的独立消融实验；策略间可能重叠。实际官方调用总数从 24,276 增至 31,968，额外预算也有贡献，但记录明确显示主要获胜路线来自新增结构候选，不能只解释成“多搜几轮”。

符合 A 规则的原因是：每个子图就是独立 Task，即使同核也要清空跨 Task 私有缓存；切开一条大张量边会增加 DDR 中转，同核切换另有 100 cycles，跨核前驱另有 1,000 cycles。把大张量依赖保留在 Task 内，同时把独立分支分给不同核心，兼顾了通信量与并行度。

例子：

- case_023 五核：加速比 1.151987 → 5.001183，子图 12 → 5，额外搬运 2,248,258 → 270,912 字节。大于 5 的加速比并不自动违法：单核整图可能有更多缓存换入换出，并非简单的固定工作量除以核数。
- case_045：1.503693 → 4.801024，子图 103 → 5，额外搬运 3,133,440 → 0。
- case_022：1 → 4.363329，子图 1 → 32。这说明“子图越少越好”同样错误；独立分量可以恢复被粗粒度方案压掉的并行性。

## 昨天 B 的问题

五核有 55 个 case 的昨天 B Makespan 甚至高于今天 A 的结果，表明优质切分没有充分传递到 B 搜索。不同方案跨硬件比较不能证明 B 必须更快，必须把 A 的具体方案在 B 下重评。

B 共 24,544 次评估尝试，6,146 次失败，占 25.04%：3,861 次顺序错误、2,279 次全局执行环、6 次子图环。仅检查子图 DAG 无环不足以保证 B 合法，核内内存依赖、Pipe FIFO 与跨核 COPY 连接后还可能成环。新版沿用拓扑插入限制和自适应执行 DAG 预检，拒绝结果不当作有效成绩。

五核搬运放大倍数 `scheduled_copy_bytes / original_graph_copy_bytes` 的中位数为 3.425。29 个 case 的 L1 峰值超过容量的 90%，但峰值接近上限不等于已经证明存在大量 spill：旧记录没有保留新增搬运的两部分拆分，本次对代表方案做了有限官方复核。

| 五核 case | 昨天 B Makespan | 切分新增字节 | 换入换出新增字节 | 主要观察 |
|---|---:|---:|---:|---|
| 057 | 43,503 | 1,356,520 | 0 | 切分通信过多 |
| 083 | 356,909 | 3,724,672 | 11,457,952 | 换入换出占新增搬运的大部分 |
| 067 | 15,905,614 | 14,951,936 | 247,863,680 | 换入换出远大于切分搬运 |

B 的同核子图合成同一个 Task，减少同核子图数量本身不再减少边界 COPY；但子图顺序会改变局部拓扑优先级、张量生命周期、换入换出和流水顺序。直接把 A 的合并策略照搬到 B 不够，还必须优化驻留和跨核数据流。

新版按原始张量的实际生产核/消费核集合计算切分搬运。多个操作消费同一张量不能按操作边重复计费：图输入每个消费核读取一次，跨核张量每个实际源核—目标核对插入一对 COPY。此模型的 pre-spill 字节数已与官方构造器对照，仍不能替代完整模拟中的 spill、等待与共享带宽。

## 昨天 L2 的问题

五核纯 Cache 平均加速仅 1.030281，100 个 case 中 70 个变快、27 个持平、3 个略慢；19 个 case 的同方案命中字节率为零。另一方面，61 个 case 的 L2 专用搜索优于固定 B 方案直接加 L2，说明算法变化和纯 Cache 收益必须分开记录。

规则核查以主赛题和 `code/multicore_cut_evaluate_problem_3.py` 为准：

1. Cache 在 COPY_IN 发射时按逻辑张量 ID 查询；读取未命中要等完成才插入。并发读取相同数据不会自动合并成一次 miss，也不保证后续读取已经命中。
2. 容量 1,048,576 bytes，FIFO 淘汰；命中不刷新顺序。大于容量的单个张量不缓存。
3. 命中走独立的 250 bytes/cycle 读带宽池，未命中 DDR 总带宽仍是 60；各池内部公平共享，不能给每核各算 60。
4. 官方使用 COPY_IN 输出侧本地张量的 `logical_tid` 或 id，不是重建的 DDR 节点 id。除原图输入外，跨核中间数据及 spill 换入也可能共享逻辑键。
5. COPY_OUT 不会自动预热 Cache。缩短 COPY_IN 耗时会改变全局事件与排队顺序，因此不能保证贪心执行下同方案总时间严格单调下降；三例轻微变慢应如实报告，不能裁成 1。

原模型把共享边固定乘 0.45，并且上一轮新版的缓存重排只追踪原始 DDR 输入，均不足以反映这些规则。本次已去掉固定折扣，并改用官方对应的本地张量读取集合；同时记录不同 miss 阶段的字节数。

case_067 的同 B 方案 L2 复核中，约 2.438 亿字节属于“曾插入后再 miss”，另约 1,282 万字节在首次读取完成前重复 miss；这支持优先缩短重用距离、减少 spill 的方向，不能靠假设所有 fan-out 都命中来分核。

case_057 是另一个重要反例：用今天 A 的优质分区后，B 和 L2 均可降至 14,028，比昨天 B 的 43,503 大幅改善；纯 Cache 加速比反而由约 1.145 降至 1。原因是需要 Cache 缓解的重复搬运已显著减少。不能以命中率或纯 Cache 比值最大作为整体优化目标。

## 已落地的修订

- 三问分别保留历史同场景最优：A 使用今天 400 个方案，B/L2 使用昨天各 400 个方案。每个方案必须官方重评成功且成绩一致，最终择优不退于该场景种子；失败则报错而非悄悄跳过。
- B 在自己的历史方案与今天 A 分区之间竞争，新增张量相关子图共同迁核，使用去重后的真实切分流量排序候选。
- 新增内存顺序候选，分别按 L1/UB 容量、每个张量后续使用者和可释放字节排序拓扑就绪子图。它是组级生命周期代理，不能精确预言核内峰值，最终只接受官方评分改善。
- 历史起点先做有限精修，再进入固定粒度/结构候选及局部搜索，避免大量相近候选挤掉“原来较慢但可以显著减少 spill”的种子。
- 修正 L2 键识别与无依据的共享折扣，保留同 B 方案配对及 L2 专用结果；新增切分/换入换出拆分和 miss 原因诊断。
- 双机依旧从相同历史种子独立生成 B。第一台计算后 50 例 B 作配对辅助；第二台计算全量 B，合并时核对重复方案和候选池。

## 有限验证与局限

17 项测试通过，新增测试覆盖真实张量计费、本地 Cache 键、同核不同子图不额外产生边界复制、内存重排不修改种子，以及官方新增搬运和 miss 字节分解。

case_057 的 12 次/场景小预算运行完成，A/B/L2 都为 14,028，并通过最终方案及 Cache 配对的官方重放。A 保持今天结果；B 比昨天减少 67.75% 的时间。该 case 的 L2 命中率下降而最终时间大幅改善，也验证了不应按命中率选最优。

case_067 的单独候选复核中，memory_order 保持切分搬运 14,951,936 字节，将 spill 从 247,863,680 降至 27,668,864，Makespan 从 15,905,614 降至 12,819,478，时间降低 19.40%。但它在 case_057 和 083 上没有改善，说明必须作为候选竞争，不能无条件覆盖旧方案。

随后使用正式批量程序对 case_067 五核 B 做 4 次候选评估预算的验证，历史种子先精修的流程实际选中了上述方案，运行状态为 complete；这确认改进已接入求解流程，而不是只存在于离线分析。

没有重新跑 100 例全量搜索，也没有测出修订版新的三问平均加速比。所有代表性提升都只适用于对应 case 和核数，不能外推为全量提升。17 项测试之外，旧版本的双机合并/续跑验证记录仍保留，但不能将旧源码实验与本次修订后的正式实验混合。

# A 题第六版算法设计（首轮可验证实现）

## 目标

以官方 A、B、L2 模拟器的 `(Makespan, added_copy_bytes)` 字典序作为唯一选优标准；每个输出都保留官方两字段方案格式。第六版先消除“新搜索偶尔丢掉旧好方案”的风险，再比较新搜索是否继续改进。图缩并搜索暂不进入首轮实现。

## 分层流程

1. **收集并验证种子。** 对每个算例、核数和场景，读取可用的第四版最终方案、第五版最终方案、Astra 精修方案。每个不同方案都先过当前官方结构校验，再用当前官方模拟器重新评估。第四版种子优先进入预算。旧记录中的分数只用于来源追溯，不参与当前选优。
2. **恢复大图粒度细化。** 当有效操作数超过 5000，先评估粗粒度 4、16、48、192、768。选其中官方分数最好的粒度，再按第四版邻域表补评三个粒度。其他第五版固定粒度与自适应候选继续参与；所有有效官方调用共享 44 次大图或 72 次小图预算。
3. **执行瓶颈引导多起点搜索。** 以当前已评估的前两个方案为独立起点。Astra 依据官方时间线轮换迁移、交换、拆分、拆分后迁移、合并等邻域；局部停滞时允许一次有限扰动。全程保留全局最优，绝不因扰动而丢弃最好方案。
4. **场景单独优化。** A 与 B 各自按本场景分数搜索，不共享搜索状态。L2 从其已有 L2 种子、当前 B 配对方案以及持久化的 B 前四名候选出发。B 作业把前四名候选及其哈希写入作业文件，断点续跑后恢复完整候选池；缺少旧版候选池时使用当时可获得的 B 种子，不伪造历史候选。
5. **统一预算账本。** A 场景先运行官方 Task DAG 顺序检查；`attempted_candidates` 记录去重后送入静态检查的候选；`static_rejected` 记录结构不合法而未调用完整模拟器的候选；`official_evaluations` 记录实际调用官方评估器次数（包含评估时报错的调用）；`official_valid` 记录成功得到合法指标的次数。搜索预算只限制 `official_evaluations`。B 方案的 L2 配对评估也计入 L2 预算。

## 不变量与验证

- 只要第四版种子能在当前官方模拟器下通过验证，第六版该配置的 Makespan 就不会比第四版更差；若 Makespan 相同，以额外搬运量较少者胜出。
- 每个最终方案及 B 候选池都保留 SHA256；运行清单锁定源码、官方代码、输入和种子方案哈希。
- 断点续跑必须使用同一份种子来源和同一份代码；来源方案变化时另开运行目录。
- 先用历史已知退步算例作定向回归，再扩大到随机/分层抽样；每轮都用官方静态校验与代表性官方复跑。

## 风险较高的后续研究

从时间线推断关键路径、跨核等待和 pipe 瓶颈有价值，但操作迁移可能引入通信、Task 等待或内存压力，诊断只用于生成候选，不能替代官方评分。“拆分 pipe 连续操作”和缩图后映射回原图更具探索性，须在首轮算法稳定后单独做消融和合法性验证。
